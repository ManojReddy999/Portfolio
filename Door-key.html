Decision-making / Dynamic programming

Door-and-key navigation

Shortest-path policies for a grid agent that may need a key to open a door, by dynamic programming over a state that tracks the task’s progress: one per known map, and a single policy for 36 random layouts.

01 / Problem

Some doors only open with a key.

An agent in a MiniGrid world must reach a goal, but a wall blocks the way except through locked doors. It may need to walk to a key, pick it up, unlock a door and only then head for the goal, or there may be a shortcut that skips the key entirely. Where the agent is is not enough to decide what to do next: which way it faces, whether it holds the key and whether each door is open all change which moves are possible.

02 / State + actions

Put task progress into the state.

Each step costs 1 and the goal costs nothing, so the cheapest policy is the one that reaches the goal in the fewest moves. Five actions: move forward, turn left, turn right, pick up the key, unlock the door.

The random maps share their walls and two door positions but place the key in one of 3 spots, the goal in one of 3, and lock or open each door. Folding those choices into the state means one policy, computed once, covers all 36 layouts: at run time the agent just reads which layout it is in and follows the table.

03 / Method and results

Backward induction, then follow the table.

Starting from the terminal cost (zero at the goal, infinite elsewhere), I stepped backwards through the horizon, computing for every state the cost of each action through the deterministic motion model and keeping the cheapest. The result is an action for every state at every step.

The policies reached the goal on all 7 known maps and all 36 random layouts, including the cases where the shortest route skips the key or takes the second door.

Scope: optimal for this discrete, fully known model; a longer path than the horizon would be missed.

04 / Limits

Every new variable multiplies the table.

  • Adding one more key position or door multiplies the state count again; exact tables stop scaling quickly.
  • The model is known and deterministic; perception and noisy actions are outside its scope.
